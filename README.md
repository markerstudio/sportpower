# نظام سبورت باور الداخلي — SportPower Internal System

نظام إدارة داخلي كامل بالعربية (RTL) لشركة **سبورت باور**، مبني وفق البريف الرسمي
وبهوية SportPower البصرية (مشروع SportPower Design System في Claude Design).

## التشغيل محليًا (وضع العرض)

```bash
npm install
npm start          # http://localhost:3000
npm run seed       # إعادة تهيئة البيانات التجريبية
```

بلا إعداد: يخزّن في `data/db.json` مع بيانات تجريبية كاملة (وضع العرض).

## النشر للإنتاج — ربط قاعدة بيانات حقيقية ✅

التخزين الدائم عبر **Postgres مُدار**: عند ضبط `DATABASE_URL` ينتقل النظام
تلقائيًا إلى Postgres بجداول علائقية حقيقية (أعمدة بأنواعها، مفاتيح أجنبية،
فهارس، وترحيلات متتبَّعة)، وخصم الحصص داخل معاملة ذرّية بقفل صف الاشتراك.

### الخطوات على Supabase + Vercel

النظام يعمل مع أي Postgres مُدار (Supabase وNeon وغيرهما) — الموصى به
**Supabase**: تسعيرة ثابتة بلا عدّاد ساعات معالجة، فلا مفاجآت في الفاتورة
مع نظام داخلي يُستخدم طوال اليوم.

1. أنشئ مشروعًا على [supabase.com](https://supabase.com) (الخطة المجانية
   تكفي للبداية — 500 MB وتبقى متاحة مع الاستخدام اليومي).
2. من **Connect** في لوحة المشروع انسخ رابط **Transaction pooler**
   (المضيف يحوي `pooler`، منفذ `6543`). هذا مهم: على Vercel تُنشأ نسخة لكل
   طلب تقريبًا، والاتصال المباشر يستنفد حدّ اتصالات القاعدة تحت الحمل.
   (النظام ينبّهك في السجل إن استُخدم رابط غير مجمَّع على بيئة لحظية.)
   لتشغيل السكربتات محليًا (`db:setup` وغيرها) استخدم رابط
   **Session pooler** (منفذ `5432`).
3. تحقق من الرابط محليًا قبل النشر — يفحص الرابط ويتصل ويطبّق الترحيلات
   ويختبر الكتابة والقراءة، وينبّهك إن كان الرابط مباشرًا بدل المجمَّع:

   ```bash
   DATABASE_URL="postgres://…" npm run db:setup
   ```
4. في **Environment Variables** أضف:
   - `DATABASE_URL` — الرابط المجمَّع. (`POSTGRES_URL` مدعوم أيضًا.)
   - `ADMIN_PASSWORD` — كلمة مرور قوية لحساب `admin` (إن لم تُضبط يبدأ الحساب
     بكلمة `admin123` مع تحذير إلزامي بتغييرها من داخل النظام).
5. أعد النشر، ثم تحقق:
   `/api/health` → `{"ok":true,"storage":"postgres","schemaVersion":2,"latencyMs":…}`
   `schemaVersion` يؤكد أن النشر طبّق كل الترحيلات.

عند أول تشغيل على قاعدة فارغة يُزرع الحد الأدنى: حساب المدير + الفروع +
مكتبة الوجبات + الباقات — بلا حسابات تجريبية. لبيئة عرض أضف `SEED_DEMO=1`.

### الانتقال بين مزوّدين (Neon → Supabase مثلًا)

`npm run db:migrate` ينقل كل البيانات من قاعدة إلى أخرى مع الحفاظ على
المعرّفات ثم يتحقق جدولًا جدولًا (العدد وأعلى معرّف). المصدر يُقرأ فقط:

```bash
SOURCE_URL="postgres://…(القاعدة الحالية)" \
TARGET_URL="postgres://…(القاعدة الجديدة — رابط Session pooler)" \
npm run db:migrate
```

بعده: `DATABASE_URL="<الهدف>" npm run db:check` للاطمئنان، ثم حدّث
`DATABASE_URL` في Vercel إلى رابط Transaction pooler وأعد النشر، وأبقِ
القاعدة القديمة أسبوعًا كنسخة احتياطية قبل حذفها. الهدف يجب أن يكون
فارغًا (`--force` يمسحه لإعادة المحاولة)، ويُستحسن إيقاف الاستخدام
دقائق أثناء النقل حتى لا تُكتب بيانات جديدة على المصدر بعده.

### الترقية من نسخة سابقة — تلقائية وآمنة

إن كانت قاعدتك تعمل بالتخزين القديم (`id + data JSONB`) فالترقية تجري وحدها
عند أول تشغيل: تُحفظ الجداول القديمة كنسخة احتياطية بلاحقة `_legacy_v1`،
تُنقل الصفوف إلى الأعمدة الجديدة بمعرّفاتها، تُنظَّف المراجع المعلّقة (يُفرَّغ
الاختياري ويُحذف الصف اليتيم إن كان المرجع إلزاميًا) مع تسجيل كل تصحيح في
السجل، ثم تُفعَّل المفاتيح الأجنبية. لا تُحذف النسخة الاحتياطية تلقائيًا —
احذفها يدويًا بعد أن تطمئن.

### متغيرات البيئة

| المتغير | الغرض | الافتراضي |
|---|---|---|
| `DATABASE_URL` | رابط Postgres (المجمَّع على البيئات اللحظية) | — (وضع الملف) |
| `ADMIN_PASSWORD` | كلمة مرور المدير عند أول زرع | `admin123` + تحذير |
| `SEED_DEMO` | زرع بيانات العرض على Postgres | معطّل |
| `PG_POOL_MAX` | أقصى اتصالات (غير اللحظية) | `10` |
| `PG_STATEMENT_TIMEOUT_MS` | سقف زمن الاستعلام | `15000` |
| `SLOW_QUERY_MS` | تسجيل الاستعلامات الأبطأ من هذا الحد | معطّل |
| `NOTIF_RETENTION_DAYS` | حذف الإشعارات **المقروءة** الأقدم من هذه المدة | `180` |
| `PGSSL_CA` / `PGSSL_NO_VERIFY` | شهادة خاصة / تعطيل التحقق (تشخيص فقط) | التحقق مفعَّل |

### التشغيل والصيانة

```bash
npm run db:setup      # ربط القاعدة والتحقق منها خطوة بخطوة (ابدأ من هنا)
npm run db:check      # فحص سلامة البيانات (ثوابت الحسابات والمراجع)
npm run db:backup     # نسخة احتياطية → backups/ (يحتفظ بآخر 14)
npm run db:restore -- backups/sportpower-XXXX.dump
npm run db:migrate    # نقل البيانات بين قاعدتين (SOURCE_URL/TARGET_URL)
npm run load-test     # اختبار حمل على قاعدة اختبار (لا الإنتاج)
```

**تمرين الاستعادة:** نسخة لم تُجرَّب استعادتها ليست نسخة احتياطية. مرة كل شهر:
أنشئ قاعدة فارغة، استعد إليها بـ `RESTORE_URL=… npm run db:restore -- <ملف>`،
ثم شغّل `npm run db:check` عليها. المزوّد يأخذ نسخه تلقائيًا (Supabase
يأخذ نسخًا يومية على الخطط المدفوعة)، لكن نسخة بيدك تعني ألا تعتمد
على مزوّد واحد.

### الأداء المرجعي

مقيسًا على بيانات سنتين تشغيل (800 متدرب · 60 ألف حصة · 45 ألف موعد ·
18 ألف دفعة) عبر `npm run load-test`:

| المسار | قبل دفع الاستعلامات | بعده |
|---|---|---|
| مسار مصادق خفيف | 11 ms | **3 ms** |
| لوحة الإدارة | 424 ms | **42 ms** |
| المتابعة اليومية | 506 ms | **14 ms** |
| مركز القرارات | 772 ms | **119 ms** |
| التقرير الشهري | 551 ms | **62 ms** |
| 20 طلبًا متزامنًا | 8.9 s | **0.8 s** |

وصفحة الاشتراكات (2410 اشتراكًا) صارت تُحمَّل صفحةً صفحة من الخادم مع بحث
في القاعدة: **‎800 KB → 11 KB** لكل فتح للصفحة.

### الأمان المطبق

- كلمات المرور: **scrypt** بملح لكل مستخدم (وليس تجزئة بسيطة).
- الجلسات: رموز عشوائية 256-bit تُخزن **مجزأة** وتنتهي بعد 12 ساعة (تمديد تلقائي).
- تغيير كلمة المرور يُنهي بقية جلسات المستخدم. زر 🔑 في الشريط العلوي.
- حد لمحاولات الدخول: 8 لكل مستخدم / 30 لكل IP كل 15 دقيقة.
- ترويسات أمان: CSP، `X-Frame-Options: DENY`، `nosniff`، وHTTPS مفروض من Vercel.
- الصلاحيات مفروضة في الخادم لكل مسار (وليس في الواجهة فقط).
- اتصال القاعدة **يتحقق من شهادة الخادم** (لا تشفير بلا توثيق هوية) —
  يمكن تعطيله للتشخيص فقط عبر `PGSSL_NO_VERIFY=1` مع تحذير في السجل.
- **سقف زمني للاستعلامات** يمنع استعلامًا شاردًا من احتجاز اتصال.
- **مفاتيح أجنبية** تمنع البيانات اليتيمة على مستوى القاعدة نفسها.
- الأسعار وتقييمات المتدربين محجوبة عن المدرب **في الخادم**، لا في الواجهة.
- الإشعارات **المقروءة** تُنظَّف تلقائيًا بعد مدة الاحتفاظ (غير المقروء يبقى دائمًا).

## أنواع المستخدمين والصلاحيات

- **الإدارة** — تبدأ من **مركز القرارات** (ما الذي يجب فعله اليوم)، وترى كل الفروع والمدربين والمتدربين. داش بورد شامل: حصص يومي/شهري،
  عدد الأشخاص وساعات التدريب لكل مدرب، المتدربون الفعالون، الاشتراكات المنتهية
  والقريبة من الانتهاء، الدفعات والتحصيلات، قراءات InBody. تعدّل البرامج والمواعيد والحصص.
- **المدرب** — حساب خاص، **لا يرى أسعار الاشتراكات ولا الباقات ولا تقييمات المتدربين**،
  جدول حصصه اليومي على Calendar، تنبيه قبل الحصة، والمدربون يتناوبون على المتدربين (الحصة تُنسب لمن نفّذها)،
  تعديل المواعيد، وتسجيل الحصة (المتدرب/التاريخ/الساعة/المدة/الأسلوب/الملاحظات/الوزن).
- **المحاسب** — إدخال المشترك الجديد (Onboarding) والتجديد والتجميد/الإلغاء بسبب مسجَّل،
  البيانات المالية: قيمة الاشتراك/المدفوع/المتبقي/تاريخ وطريقة الدفع، المجددة والمنتهية،
  إضافة وتعديل الدفعات، تسجيل **المصاريف الشهرية** ورؤية **صافي الربح**، متابعة المبيعات (Leads)،
  بروفايل كل متدرب (بياناته واشتراكاته ومدفوعاته)، والأهداف الشهرية/السنوية بوضوح مع الترحيل.
- **المتدرب** — **باقته الحالية والباقات المتاحة**، **تقييم كل حصة أخذها مع تعليق يصل للإدارة**،
  رصيد الحصص (الكلي/المستخدم/المتبقي)، جدول مواعيده، قراءات الوزن
  والـ InBody مع مقارنة، ملاحظات المدرب، تاريخ الاشتراك والانتهاء، برنامجه الغذائي والتدريبي،
  وقسم **«نقاطي ومكافآتي»**: نقاط الولاء وسجلها والمكافآت وكود «ادعُ صديقًا».

## نظام الحصص (منطق الاحتساب)

عند حفظ حصة من المدرب:
1. تُحفظ الحصة باسم المتدرب وتُخصم حصة من رصيده ويظهر له «متبقي 11 من أصل 12».
2. تُضاف لأداء المدرب الشهري (عدد الحصص + عدد الأشخاص).
3. تُسجل الساعة التدريبية: **شخصان بنفس الساعة = ساعة تدريب واحدة، وعدد الأشخاص = 2**
   (الساعات تُحسب بالساعات المميزة: مدرب + تاريخ + ساعة بدء).
4. الأرقام تتحدث تلقائيًا في كل اللوحات.

## مركز القرارات (Action Center) — «ماذا يجب أن نفعل الآن؟»

الصفحة الأولى للإدارة والمحاسب: لا تعرض أرقامًا فقط، بل **يحوّل النظام كل مشكلة
يكتشفها في البيانات إلى إجراء جاهز للتنفيذ**. لكل بطاقة: سبب ظهورها، أولويتها،
الشخص أو الفرع المسؤول، وأزرار تنفيذ مباشرة (اتصال · واتساب · فتح ملف المتدرب ·
فتح ملف التجديد · فتح ملف المدرب · إنشاء مهمة).

| الأولوية | القاعدة | الإجراء المقترح |
|---|---|---|
| 🔴 عاجل | متدرب غاب أكثر من مرة خلال 30 يومًا | مهمة تواصل + إعادة جدولة |
| 🔴 عاجل | اشتراك بقي له حصتان أو أقل / ينتهي خلال أسبوع / منتهٍ | مهمة تجديد مع عرض الباقة |
| 🔴 عاجل | متدرب غاب ولم يتم التواصل معه بعده | إشعار لقسم المتابعة |
| 🔴 عاجل | تقييم منخفض (≤2) من متدرب لحصته | مراجعة مع المدرب وإغلاق الشكوى |
| 🟡 مهم | مدرب لم يسجل قياسات لمتدربيه خلال أسبوعين | مهمة مراجعة للمدرب |
| 🟡 مهم | متدرب بلا تقدّم خلال 4 أسابيع (حسب هدفه) | مراجعة الخطة التدريبية والغذائية |
| 🟡 مهم | انخفاض نسبة التجديد في فرع عن الهدف | تنبيه للإدارة مع مراجعة الأسباب |
| 🟢 تحسين | ارتفاع نسبة الغياب في فرع | تفعيل التذكير ومراجعة المواعيد |
| 🟢 تحسين | التحصيل متأخر عن الهدف اليومي (الهدف الشهري ÷ أيام الشهر) | متابعة الدفعات والتجديدات |
| 🟢 تحسين | انخفاض معدل حضور المتدربين النشطين | حملة تنشيط وحجز مواعيد |
| 🟢 تحسين | ملاحظة مكتوبة من متدرب على حصته | الاستفادة منها في تحسين التجربة |

- **تنفيذ وتتبّع**: «تم التنفيذ» مع تسجيل النتيجة، «تأجيل» لمدة تختارها، وإعادة الفتح —
  وكل ذلك في **سجل الإجراءات** (من نفّذ، ومتى، وبأي ملاحظة).
- **تحويل الإجراء إلى مهمة**: بضغطة تصبح مهمة رسمية على مدرب، تصله بإشعار وتدخل في KPI الشهري.
- **العتبات قابلة للضبط** من المدير (عدد الغيابات، الحصص المتبقية، أيام القياسات، نسب
  التجديد والغياب والحضور…) ويُعاد الفحص فورًا وفقها.
- ملخّص المركز يظهر أعلى لوحة الإدارة قبل الأرقام، ويمكن فلترة الإجراءات حسب الفرع والأولوية.

## الباقات والعقد الإلكتروني

- **الباقات**: كتالوج اشتراكات (اسم، عدد حصص، سعر، مدة، حصص أسبوعية، ما تشمله الباقة)،
  تظهر على **ملف كل مشترك** للتجديد أو الترقية، وتملأ نموذج التسجيل تلقائيًا.
- **العقد الإلكتروني**: الإدارة تفتح رابط عقد وترسله للزبون على واتساب — يفتحه **بلا حساب**،
  يرى **كل الباقات بأسعارها** وسعر الحصة وشروط الاشتراك، يختار باقته ويعبّي بياناته
  (بما فيها الملاحظات الصحية ورقم الطوارئ) ويوافق على الشروط. تصل بياناته للإدارة
  وتحوّله لمشترك بضغطة واحدة (Onboarding معبّأ مسبقًا بباقته وبياناته).
- **سرّية الأسعار**: المدرب وأخصائية التغذية **لا يريان أي سعر** — لا في ملف المشترك،
  ولا في الاشتراكات، ولا في الباقات (مفروض في الخادم وليس في الواجهة فقط).

## تقييم الحصص — خاص بالإدارة

المتدرب يقيّم كل حصة أخذها (من 1 إلى 5 نجوم) ويكتب تعليقه بحرّية. التقييم والتعليق
**يصلان للإدارة فقط ولا يراهما المدرب إطلاقًا** (مفروض في الخادم). صفحة «تقييمات المتدربين»
تعرض المتوسط العام، متوسط كل مدرب (الأدنى أولًا)، وكل التعليقات — وأي تقييم منخفض
يتحول تلقائيًا إلى إجراء عاجل في مركز القرارات.

## الميزات

- **Calendar مشترك** أسبوعي: الإدارة تضيف مواعيد وترى جدول كل المدربين معًا مع فلتر،
  المدرب يرى مواعيده ويعدلها، وتصل إشعارات عند الإضافة أو التعديل.
- **InBody Reader**: رفع صورة القراءة، محاولة قراءة تلقائية OCR (عبر tesseract.js إن توفر —
  مع نموذج يدوي دائمًا)، حفظ كل القراءات حسب التاريخ، ومقارنة (الوزن/الدهون/العضلات/الماء/BMI).
- **الإشعارات**: مواعيد جديدة أو معدلة، تنبيه قبل الحصة، اشتراكات قريبة من الانتهاء، خصم الحصص.
- **التقارير الشهرية** لكل مدرب وفرع + تصدير **Excel (CSV)** و**PDF (طباعة)** — وتشمل
  **تقرير النمو** وفق مؤشرات الشركة: المشتركون الجدد، المجددون ونسبة التجديد (Retention)،
  الإلغاءات ونسبتها وأسبابها، المجمدون ونسبتهم، النمو الصافي (Net Growth)، النشطون،
  متوسط بقاء العميل، قيمة العميل (LTV)، والمقارنة بالهدف الشهري والسنوي.
- **المصاريف الشهرية وصافي الربح**: المحاسب يسجل مصاريف كل شهر (رواتب/إيجار/تسويق…)
  وتظهر في التقرير الشهري مع التحصيل وصافي الربح.
- **الأهداف مع الترحيل التلقائي**: الهدف الشهري لكل فرع ظاهر بوضوح، الهدف السنوي مقسم
  على أشهر السنة، وما لم يتحقق من هدف شهر منقضٍ يُرحَّل تلقائيًا لهدف الشهر التالي.
- **متابعة المبيعات (Leads)**: ملف بكل رقم تم التواصل معه (القناة، السكن، الهدف، المرحلة،
  الاعتراض)، وتحليل شهري: نسبة الإغلاق، أين مشاكل المبيعات (غالي/بعيد/لم يحضر التجربة…)،
  وتحويل العميل المحتمل لمشترك بضغطة واحدة.
- **نظام الولاء «نقاطي ومكافآتي»**: نقاط عند حضور الحصص وتجديد الاشتراك وتحقيق الأهداف
  (منح يدوي من الإدارة)، مكافآت قابلة للاستبدال (خصم/بلوزة/حصة إضافية/شهر مجاني)
  باعتماد الإدارة، وتحكم كامل بقيم النقاط والمكافآت.
- **الإحالات «ادعُ صديقًا»**: كود خاص لكل مشترك ومشاركة عبر واتساب (للاشتراك أو لحصة
  تجريبية)، اعتماد الإحالة من الإدارة يمنح المُحيل نقاطه، مع تقارير بالإحالات والاستبدالات.
- **الحصص التعويضية**: خيار «تعويض» في الجدول اليومي وتسجيل الحصص — تُسجل باستقلال
  عن الحصص العادية وبلا خصم من رصيد الاشتراك.
- **البرامج التدريبية**: المدرب ينشئ برنامجًا فيُربط تلقائيًا بكل المتدربين ويصلهم إشعار.
- **مكتبة التغذية**: وجبات بالسعرات والماكروز والمكونات وطريقة التحضير والنوع والهدف،
  إضافة من المدرب/الأخصائية، عرض حسب هدف المتدرب، بحث وفلترة (سعرات/بروتين/نوع/هدف)،
  وربط الوجبات ببرنامج المتدرب اليومي.
- **سهل الاستخدام على الموبايل والكمبيوتر** — واجهة متجاوبة بالكامل.
